# LocalModAI — Preview-сборки

LocalModAI — локальная модульная ИИ-платформа в активной разработке.

Сейчас проект находится на стадии **MVP 0.5 Preview**. Это ранняя тестовая версия для Windows, а не готовый продукт.

## Что можно проверить в v0.5.0-alpha.4

- создание и открытие проектов;
- несколько связанных чатов внутри проекта;
- локальные GGUF-модели через встроенный `llama.cpp Runtime Pack`;
- внешние API через Диспетчер мозга;
- Planning Intake и создание Plan Candidate;
- принятый рабочий план и Project State;
- фоновые BASE / CHECKPOINT итоги длинных сессий;
- восстановление фоновой работы после части ошибок;
- Manual Retry — ручной повтор остановленной фоновой задачи;
- Attention Center — первый рабочий контур для фоновых проблем;
- журнал ошибок и диагностики;
- настройки фоновых итогов, API-разрешения и timeout;
- светофор реального состояния мозга и фоновой работы.

## Что особенно нужно протестировать

Нам особенно полезны результаты на железе и моделях, которых нет у разработчика:

- 14B / 24B / 27B / 32B+ GGUF;
- NVIDIA / AMD / CPU-only;
- 32 / 64 GB RAM;
- разные quantization;
- reasoning-модели;
- модели с большим context window;
- другие API / OpenRouter модели.

## Важно

Это alpha-версия.

Техническая надёжность фоновой работы сильно улучшена, но **смысловая точность Summary ещё не финальная**.

Модель иногда может:

- усилить предложение до решения;
- перепутать автора утверждения;
- неверно интерпретировать открытый вопрос;
- перенести мусор исходного диалога в итог.

Поэтому важные решения и факты нужно проверять.

## Как установить

1. Откройте раздел **Releases**.
2. Скачайте `LocalModAI-v0.5.0-alpha.4-windows-x64.zip`.
3. Полностью распакуйте ZIP в отдельную папку.
4. Запустите `LocalModAI_MVP.exe`.
5. Добавьте совместимую GGUF-модель через папку `Models` / Диспетчер мозга.

Не запускайте приложение прямо из ZIP.

Windows SmartScreen или антивирус могут показать предупреждение: тестовая сборка пока не подписана цифровой подписью.

## Как сообщить об ошибке

Для технической ошибки помечайте отчёт как **TECH BUG**.

Для неверного смысла итогов помечайте как **SUMMARY QUALITY**.

Перед отправкой диагностических файлов проверьте, что в них нет личных данных, текста приватных проектов и API-ключей.
