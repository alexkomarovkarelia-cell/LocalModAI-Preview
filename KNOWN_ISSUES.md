# Известные ограничения v0.5.0-alpha.5

Это ранняя тестовая версия.

## Workspace / Рабочие файлы

AI-действия с файлами в alpha.5 намеренно ограничены безопасным минимальным сценарием.

Сейчас моделью поддерживаются прежде всего:

- создание текстового файла;
- запись явно заданного текста;
- чтение существующего текстового файла;
- повторное чтение после создания, если это требуется задачей.

Пока не считаются готовыми для публичного сценария:

- создание папок моделью;
- сложное AI-редактирование существующих файлов;
- массовые файловые операции;
- неточный / семантический поиск файла по описанию;
- сложное разрешение фраз вроде «тот файл, который мы делали вчера».

Файлы, открытые во встроенном редакторе, читаются моделью из сохранённого состояния на диске. Несохранённые изменения редактора не должны считаться доступными Workspace-чтению.

## Повторные попытки и скорость

Новый Workspace Trust-слой может увеличить время ответа отдельных локальных моделей.

Если модель:

- не вызывает обязательное Workspace-действие;
- выбирает неправильный шаг;
- пытается преждевременно сообщить «готово»;

LocalModAI может отклонить такой результат и повторить попытку или безопасно довести однозначную операцию ядром.

Поэтому один пользовательский запрос иногда включает несколько внутренних model rounds. На медленных локальных моделях это может заметно увеличивать общее время выполнения.

## Summary Quality

Технический контур BASE / CHECKPOINT / Recovery прошёл большую серию тестов и дополнительно усилен в alpha.5, но смысловая точность итогов ещё не финальная.

Возможны случаи:

- предложение модели выглядит как принятое решение;
- открытый вопрос выглядит как отклонённый вариант;
- слова ИИ приписываются пользователю;
- будущее действие выглядит как уже выполненное;
- модель упрощает или теряет важный факт неудачного взаимодействия;
- часть смыслового шума исходного диалога переносится в долговременный итог.

Перед использованием Summary как основы важного решения проверяйте исходный чат.

## Plan-aware Summary

Полная связь Summary с accepted plan, current item, completed items и Work Outcomes ещё не закрыта.

Это следующий отдельный этап качества.

## Background worker / Recovery

В alpha.5 усилены cursor / chunk / summary reconciliation, logical work recovery и фильтрация неподтверждённых технических сообщений.

При этом сложные редкие комбинации crash / restart / model failure всё ещё могут выявить новые граничные случаи. Если фоновая задача остановилась или выглядит подозрительно, приложите к TECH BUG диагностические данные и состояние задачи.

## Модели и железо

- разные GGUF-модели дают сильно разные результаты и скорость;
- большие модели могут работать очень медленно или не запуститься при нехватке RAM/VRAM;
- крупные 14B / 24B / 27B / 32B+ модели не могут быть полноценно проверены на железе разработчика;
- reasoning-модели могут требовать дополнительных recovery-ступеней;
- некоторые слабые модели хуже соблюдают tool / Workspace-инструкции и поэтому чаще попадают в повторные попытки.

## Windows

- при очень долгой локальной генерации переход Windows в сон может нарушить работу runtime;
- цифровой подписи Windows пока нет;
- автоматического обновления пока нет;
- Windows SmartScreen или антивирус могут показать предупреждение для тестовой unsigned-сборки.

## Интерфейс / архитектура

- Attention Center пока в первую очередь охватывает фоновые проблемы;
- единый Error Protocol развивается и ещё не охватывает абсолютно все события программы;
- Plan Context Audit остаётся незакрытым;
- сложный multi-chat memory selection и document/TZ planning ещё не завершены;
- UI и backend всё ещё содержат крупные модули, их разделение отложено до стабилизации текущего MVP-контура.

## Безопасность

Не храните в тестовой версии:

- пароли;
- платёжные данные;
- секретные ключи;
- критически важную личную информацию.

Перед публикацией диагностического архива проверьте его содержимое вручную.
